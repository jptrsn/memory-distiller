## Host device pass 2026-11-23 — cause identified. Single culprit: a deferred
`context.read` in the drawer closure, run by the pushed route's lazy page
builder after `popUntil` popped the drawer's own route.

### The confirmed culprit (one site)

`_open` passes a closure that reads providers through the drawer element's own
`BuildContext`, which the pushed route evaluates lazily and repeatedly.

### Mechanism

1. Drawer opened from a pushed screen; `popUntil` pops the route that owns the
   captured context.
2. Every later rebuild of the route re-executes the closure on a defunct element.

### Reproduction (verified twice on the Pixel 6; deterministic)

1. Debug build on the device, connected to a server.
2. Open drawer on root → tap Queue (creates a pushed screen).
3. On the pushed screen, open drawer → tap Settings; then toggle the theme.

### Why the suite stayed green

No test taps Settings from a pushed route, and none rebuilds a pushed route's
content after the pop settles, so `takeException()` never reaches the failing
frame.

### Answers to the triage questions

1. Severity stays `low`: the assert compiles out in release builds.

### Plan for completion (separate unit; not implemented here)

1. Read the providers eagerly at tap time.
